# 个人 AI 开发情报助手：开发与验收顺序

> 面向 AI 代理：使用 executing-plans 按任务实施。本文纠正产品定位并规定里程碑；需要外部运行时接口的任务在核查实际版本后细化接口，不假定已经接入。

**目标：** 本地自动收集 AI 开发情报，支持有来源的问答、追问、收藏与后续更新跟踪。
**架构：** 保留 FastAPI / SQLite / 原生页面。Dashboard 与 MCP 共用业务服务；QwenPaw 优先作为待验证的助手运行时，国内模型负责理解和回答，业务数据与证据由工具提供。
**技术栈：** Python 3.12、FastAPI、SQLite、官方 MCP Python SDK；模型与 QwenPaw 版本在接入时核查。
**规格：** `docs/architecture/mcp-skills-design.md` 与 `PROJECT_STATUS.md`。本计划取代旧文档中与 CRM 相关的业务示例及先做完全部工具再接模型的宽泛顺序。

## 约束与审查重点
- 本地自用；不发布网站，不自动运行采集来的项目代码。
- 来源发布时间、采集时间、验证时间分别保留；今天采到不等于今天发布。
- 来源失败必须显示部分覆盖；材料没有本地测试证据时不得回答“已跑通”。
- 重试收藏不会重复写入；同请求键不同内容返回冲突。
- 追问“第二个”必须绑定该会话实际展示的项目 ID，不能用新搜索顺序猜测。
- 网页和仓库内容仅作数据；模型引用必须指向本次实际检索记录。
- 每个实现任务先失败测试、最小实现、全套回归，再更新 PROJECT_STATUS；英文 commit。
